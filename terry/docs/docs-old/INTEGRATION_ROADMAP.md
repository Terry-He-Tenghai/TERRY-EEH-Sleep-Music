# 脑电监测与音乐增强：集成路线与验收

更新：2026-09-12。当前是研究实验台，不是已验证有效的助眠医疗系统。

## 本轮边界

- Web 采集支持 250/500/1000 Hz，命令对应 ~6/~5/~4；采集中禁止切换。
- 演示、时间戳和显示窗口按实际请求采样率计算。设备是否实际按配置输出仍须通过采样计数、设备时间戳、包序号和长时间测试验证。
- 脑电与手动离线音乐可在同一页面使用。播放器只使用已审核素材，不在线生成，不自动播放。
- Python 已有的音乐增强、状态推理模块不等于已接入浏览器；手动音量渐变不等于分层生成或自动助眠。

## 下一阶段实施顺序

### 1. 信号可信度（自动控制前置条件）

逐通道确认物理帽位、参考电极、硬件增益到微伏换算、饱和与脱落检测；确认设备序号、时间戳、真实接收率与丢包率。独占设备分别完成 250/500/1000 Hz 至少 30 分钟测试。

显示支路增加可选的有状态高通/低通/工频陷波，保留原始数据，明确与 OpenBCI 的相同参数；不能把去均值等同带通。显示丢帧不可传递为模型丢样本。

### 2. 在线状态模型与质量门控

复用硬件 16 通道模型和既有 RealtimeSession。先核对其训练通道、参考、单位、窗口、归一化与模型版本。

500/1000 Hz 输入先连续抗混叠重采样到模型要求的 250 Hz，保存滤波状态和时间对齐；测试不同输入采样率同一波形的特征与预测一致性。窗口不足、脱落、饱和、断流均产生“不可用”，不能冒充清醒或入睡。

验收：离线录制回放可复现 W/N1/N2 概率、未来 N2 风险和质量标志。概率仅为模型估计，不是临床睡眠诊断。

### 3. 分层音乐渲染与状态控制

将经审核的 pad/melody/bass/texture 同步轨道接入 Web Audio 或服务端渲染；共享时间轴、循环点、调性和节拍。普通 Suno 成品不能自动视为四个可独立控制的音轨。

先实现手动 M1/M2/M3、分层增益及乐句边界切换，再接既有调度器；加入状态滞回、最短保持、音量限幅、连续淡变。信号无效立即冻结自动调度，保持保守音量或平滑停止；用户始终可停止。

验收：固定状态序列产生可复现控制事件；曲目切换、失焦、WebSocket 断开、浏览器禁止自动播放均正确处理，无突发音量。网页音量百分比不能代替耳旁声压测量。

### 4. 可追溯实验

统一 session_id，保存同意信息、模型/配置/素材版本与哈希、硬件时间、质量事件、状态概率、控制命令与实际播放事件。原始 EEG 和可识别记录默认本地存储、不提交 Git。

设置固定音乐、总音量、分层波形、分层波形加 MIDI 四组条件，预先确定结果指标、随机化和排除标准。提示词、模型输出和主观试听都不能证明改善入睡效果。

### 5. 发布验收

后端单元与接口测试、前端生产构建、浏览器播放实测、真实帽三档采样率稳定性、断网/失联恢复、停止/重连并发、不同增益校准全部通过；记录设备固件及软件版本后才启用自动模式。
