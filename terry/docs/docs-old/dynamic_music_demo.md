# 动态音乐演示与模型验证

## 使用

重启后端并刷新前端。数据源选择“演示信号”，选择250Hz以及任意BabySlakh曲目（默认Track00008），点击开始采集。

约3秒合成数据后产生首个音乐计划，加载完音频即可播放，无需等待300秒基线。预设时间轴（以合成样本时间计）：
- 0–24秒：W / M1，概率权重0.94/0.04/0.02。
- 24–48秒：N1 / M2，权重0.08/0.86/0.06。
- 48–72秒：N2 / M3，权重0.02/0.08/0.90。
- 72–96秒：W / M1；随后96秒循环，边界前后均是W，故不会每个边界都有听感变化。

每3秒发计划。分轨混音3秒渐变，MIDI声部在16秒乐句边界应用。动态演示取消控制量的20秒平滑，仍保留音频增益/包络渐变；可看到不同旋律密度、M3退出旋律低音，以及原曲钢琴/弦乐比例差异。DEMO波形按同一时间轴改变alpha/theta/delta组成，但这些波形没有被模型分类得出上述概率。

若选择“模型验证”，则保留原模拟波形→真实模型→300秒基线/质量门控流程，不能保证模型输出按指定状态变化。想验证模型能否识别阶段变化，需要带标签的真实EEG回放，不应修改模型输出以达到展示效果。

## 明确的来源隔离

API增加demo_profile=model|showcase，默认model，避免旧客户端行为改变。前端明确默认showcase用于展示。brainflow+showcase和非250Hz showcase会返回422；切换到真实设备时前端只发送model。

showcase事件：source=DEMO、demo_scripted=true、playback_mode/inference_mode=demo_scripted、probability_origin=scripted_not_model、demo_stage、demo_elapsed_s。state.status=demo_scripted、baseline_ready=false、未来N2概率=null。signal_quality=1仅表示本批合成数据有效，signal_quality_scope明确标记，不代表真实电极质量。

保留probabilities字段用于音乐输入兼容，但界面显示“预设权重/非机器学习预测”，不显示成有效模型分类。日志保存来源标记。分轨stem_mix.mode同样为demo_scripted。前端拒绝带脚本标记的LIVE事件或不一致来源字段。

showcase不加载模型权重，但通过合成采集队列驱动；停止采集、时间不连续、非有限值、积压、断流、页面隐藏、音频上下文中断等保护保留。不会脱离采集无限自动产生新有效事件。仍需可用本地音频，推荐已集成的BabySlakh；Suno库缺曲或上传缺失不能靠演示模式解决。

## 验证范围

后端回归覆盖完整96秒状态周期（加速喂入合成样本）、缺少模型文件、原模型默认、LIVE拒绝、时钟/断流/停止/非有限值；音乐及分轨相关207项通过，1项Windows实际符号链接权限跳过。前端覆盖两个音频引擎的DEMO来源接受与LIVE伪装拒绝，28项通过。

真实时间浏览器集成已通过（约55秒观察W→N1→N2、原曲声部节点变化且持续播放），测试未注入概率或加速时钟；由showcase后端实际产生预设事件。这是音乐链路验证，不是机器学习分类有效性验证。

`frontEnd/browser-tests/demo-showcase.spec.js`为可选真实时间集成测试，需要本地数据及8011隔离后端，通过页面开始采集，真实后端产生W/N1/N2事件，再验证声部节点值变化（非真人机器学习准确率测试）。
