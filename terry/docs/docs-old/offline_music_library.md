# 离线音乐素材库与网页手动播放（独立模块）

## 2026-09-13 当前播放规则

按用户要求，网页音乐库已取消人工审核门槛：清单登记的本地音频只要文件存在、路径安全且扩展名受支持，即可手动播放；pending、rejected 或未填写审核/许可均不影响试听。页面不再显示审核信息，历史记录不修改。仍拒绝目录逃逸、符号链接和不支持的文件类型，保留手动点击、音量上限和停止逻辑。独立素材冻结工具的审核要求不变。下文旧版审核部署说明仅作历史参考，播放资格以本节为准。

自动生成候选音频现可使用独立命令行工具，见 `AISAASGO_SUNO_API.md`。生成不等于审核通过，播放器依旧只读取经人工批准的本地素材。

## 边界与集成

这是本机只读音频目录和手动播放器，不上传、下载、调用 Suno 或根据脑电自动播放。仓库不提供实际音乐文件，也不将生成音频视为已经获得授权。用户点击播放后才请求音频，缺少素材时页面正常显示空库。

- 后端：在 `backEnd/app.py` 使用与启动方式相适配的导入：从 backEnd 目录启动时 `from music_library import router as music_router`，然后在已有 FastAPI 实例上调用 `app.include_router(music_router)`。路由已经包含 `/api/music` 前缀，不要再重复添加。
- 前端：在 `frontEnd/src/App.vue` 的 script setup 中导入 `MusicPanel`，路径为 `./components/MusicPanel.vue`，在模板中放置 `<MusicPanel />`。无 props，无脑电状态依赖。
- 开发环境需要将同源 `/api` 转发到后端；生产环境使用同源反向代理。不使用外部音频 URL，也不依赖 `VITE_API_BASE`。
- 不要把 `backEnd/music` 直接挂为静态目录，否则可能绕过审核限制。本模块没有审核写接口，审核只能由本地管理人员编辑清单。

## 本地文件与清单

手动建立 `backEnd/music/manifest.json`，音频可以放在其子目录（例如 `backEnd/music/ambient/quiet-pad.mp3`）。将 `docs/music_manifest.example.json` 复制为 manifest 后再按真实资料填写。示例默认 `pending`，不含真正批准或授权断言；没有文件时仍不可播放。

顶层严格为 `version: 1` 和 `tracks` 数组。每条字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 唯一稳定 ID，1–64 个字母/数字/下划线/连字符，首字符字母或数字 |
| `title` | 显示名称 |
| `file` | 相对于 music 的本地路径，绝对路径、`..`、反斜杠和符号链接禁止 |
| `purpose` | 中文素材用途；不是临床疗效宣称 |
| `source` | 来源说明、生成平台/日期或原创作者，作为纯文字显示 |
| `license` | 实际授权依据和适用范围，不能只凭生成提示词推断 |
| `review.status` | `pending` / `approved` / `rejected` |
| `review.reviewed_by` | 实际审核人 |
| `review.reviewed_at` | 实际审核日期 YYYY-MM-DD |
| `review.copyright_checked` | 已人工核对版权/使用范围，布尔值 |
| `review.audio_checked` | 已全曲听审与技术检查，布尔值 |
| `review.notes` | 审核记录、问题和处理过程 |

只有 `approved`、审核人及日期齐全、两项检查为 true、授权说明非空、音频路径安全且文件存在时才可获取。支持 mp3/wav/ogg/m4a/flac；具体编码是否可播取决于浏览器。文件扩展名检查不等于音频内容检测，全曲听审和格式验证由操作者负责。清单最大 1 MB、1000 条；未知字段、重复 ID、错误 JSON、错误类型使整个清单失败关闭，返回空库且 `status=invalid`。

## HTTP 接口

- `GET /api/music`：`{status: "ready" | "missing" | "invalid", tracks: [...], control_mode: "manual", message: "..."}`。返回所有合法清单条目的审核元数据；未审核或缺文件条目 `available=false, audio_url=null`。从不返回 `file` 或绝对路径。
- `GET /api/music/{id}/audio`：每次重新检查清单与路径，合格返回音频文件，可处理浏览器 Range 请求。不存在、审核不足、越界和不支持类型统一 404。
- 无上传、修改、审核或在线生成接口。响应 `Cache-Control: no-store`，音频另加 `nosniff`。

缺清单时为空库；只有清单但缺音频时保留审核记录、标记不可播放。撤销审核会拒绝之后的请求，不能撤回已经下载、缓冲或正在传输的字节。接口没有用户身份认证，仅适用于可信本机/受保护内网；审核信息也会对接口访问者可见。部署到公网前必须另外增加认证、访问控制及隐私评估。

路径检查防止 manifest 引用越界、符号链接与任意路径请求；此处不是对恶意本机写入者的沙箱。必须通过操作系统权限限制 music 目录写入，在停止播放/服务后更新素材，避免校验后文件被其他进程替换的竞态。已审核音频被改写后应重新审核，建议运营记录 SHA-256 校验值（当前接口尚未自动校验内容哈希）。

## 播放安全与人工审核流程

1. 在平台外部人工生成/创作并下载，记录平台版本、生成日期、账号/套餐和使用条款快照；确认是否允许展示、科研、再分发或商业用途，必要时询问权利人。
2. 全程试听，排除语言、人声、骤响、强鼓点、警报、突兀转调、突然结束、过强低频与数字削波；检查开头和结尾。
3. 用音频编辑器手动调整开头/结尾淡入淡出、响度一致性、峰值裕量；检查导出后的最终文件，不能仅审核编辑前版本。
4. 登记 `pending` 条目、授权证据与试听记录；真正审核完成才改成 approved 并填写真实审核人、日期与两项确认。批准不是医学安全认证。
5. 低设备音量下点击播放，观察是否缓慢淡入、可暂停、立即停止、切曲不播放、后台停止、结束不自动切曲或循环。

组件默认目标音量 15%，范围 0–40%，播放从零约 1.5 秒淡入；音量调整约 1.5 秒，普通暂停约 0.8 秒淡出。紧急停止/切曲/隐藏页面/卸载立即暂停静音。系统音量、扬声器、耳机和听力差异决定实际声压，百分比不保证安全。部分移动浏览器可能限制 HTMLMediaElement 音量设置，需在目标设备实测；不以程序音量上限代替声压校准。

## 后续脑电闭环：尚未实现

1. 先建立固定刺激与安静对照的研究设计、知情同意、伦理和退出规则。明确结果指标，不宣称 EEG 某频段变化等于进入睡眠或治疗成功。
2. 将采集时间、播放时间与用户操作写入统一时钟事件日志；记录信号质量、伪迹、缺失、设备断开。当前播放器没有这些研究日志。
3. 使用有验证依据的滤波、伪迹处理和个体基线，严格区分演示数据与真实数据；离线验证后再实时推断。不得直接用未经验证的单一频段阈值闭环。
4. 增加单独的策略模块和显式用户授权开关；先以“仅建议、不执行”的方式验证。设置平滑、迟滞、最短驻留、最大调节速率与音量硬限制，防止频繁来回切换。
5. 闭环失效时采用预先约定的保守静音/保持策略，手动停止始终最高优先级；断连、信号差和低置信度不得触发加大音量。
6. 首版只控制经过审核的整曲音量或少量固定素材，必要时实现经过试听的交叉淡化。分轨、实时混音和在线生成不属于本版本。
7. 正式对比需预注册或提前固定评价流程、被试级隔离、适量样本、负面反应记录和研究人员监督；不能由控制界面推导疗效。

## 验证

- 前端：在 frontEnd 执行 `node --test src/components/MusicPanel.test.mjs`。
- 前端测试编译 Vue 单文件组件，并用音频对象模拟验证点击、渐变、拒绝未审素材、异步停止、切曲和页面清理。模拟测试不等同于真实浏览器音频/听力安全验证。
