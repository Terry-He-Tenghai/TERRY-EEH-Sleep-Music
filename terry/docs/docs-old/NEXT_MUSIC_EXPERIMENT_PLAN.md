# 首版代码交接与后续音乐实验计划

## 1. 本文目的

本目录是 Terry 项目的第一版可运行代码。首版已经跑通：

```text
连续 EEG 数据
→ 因果预处理
→ W/N1/N2 状态概率与未来 N2 预测
→ 五模式音乐策略
→ Suno 音乐缓存/播放命令
```

后续工作应以首版为基线，优先增强音乐层，不先修改已经完成的 EEG 模型和实时数据接口。

## 1.1 2026-09-06 实施状态

本轮已经完成音乐增强基础模块：四层本地混音、M1/M2/M3 状态、确定性 MIDI 动机与质量指标、波形处理指标、乐句边界调度、无效信号冻结/回退标记，以及 `music-render-demo` 离线演示命令。首版 EEG 处理和实时采集接口保持不变。详细记录见根目录 `进度.md`，Suno 素材提示词见 `docs/SUNO_AUDIO_PROMPTS.md`。

当前仍未完成：真实素材冻结流程、四种消融条件批量回放、实际音乐事件日志/重渲染工具、专业音色合成和网站界面。上述项目仍需试听、安装依赖和实验验证后推进。


### 已有能力

- 16 通道 EEG 离线处理和实时数据契约；
- 受试者留一验证的 W/N1/N2 状态模型；
- 未来 5 分钟稳定 N2 预测模型；
- 每 3 秒输出状态，音乐策略每 30 秒决策；
- 五种音乐模式：高觉醒降低刺激、放松稳定、N1 过渡、微觉醒修复、N2 保护；
- Suno 异步生成、回调/轮询、缓存和人工审核接口；
- pygame、VLC 和空播放器适配器；
- 无网络的 `music-demo` 策略演示；
- 测试、配置和研究文档。

### 当前音乐端的限制

首版当前主要做：

```text
EEG 状态
→ 五模式状态机
→ 选择缓存音轨、交叉淡入、叠加、淡出或停止
```

这意味着：

- Suno 生成的是完整音轨，音乐内部结构不能被精确控制；
- 运行时主要控制播放动作，不控制旋律、声部和音色结构；
- 还没有四层分轨混音；
- 还没有波形级滤波、混响、空间宽度和动态包络控制；
- 还没有自主 MIDI 和声、低音或动机层；
- 还没有固定音乐、只调音量、分层控制和双层引擎的音乐消融实验；
- 当前音乐策略中的阈值是初始工程参数，不是已经证实的 EEG—音乐规律。

因此，Suno 可以继续作为离线素材工具，但不能作为后续项目的核心音乐创新。

## 3. 后续项目目标

后续目标是将首版改造成：

> 一个将可信 EEG 状态转换为连续音乐变化的双层音乐引擎。

目标架构：

```text
EEG 状态输出
        ↓
音乐状态控制器
        ↓
符号层：MIDI、和声、动机、声部、乐句
        ↓
波形层：分层增益、滤波、混响、空间、响度包络
        ↓
本地实时混音输出
        ↓
保存状态、参数、MIDI、音频和事件日志
```

## 4. 必须保留的首版内容

后续改造不应破坏以下接口：

- `EegChunk` 输入契约；
- `RealtimeSession.push()`；
- `StateUpdate` 和 `RealtimeOutput`；
- 现有 EEG 预处理、状态模型和未来 N2 模型；
- `MusicController.update(state)` 注入点；
- `music-demo` 无网络策略演示；
- 现有 Suno 缓存和人工审核能力；
- 现有测试和配置文件。

新增音乐功能应尽量实现为独立模块，通过现有 `MusicController` 或新增适配器接入。

不应为了增加音乐功能而重新训练或修改 EEG 模型，除非出现明确的接口或通道不匹配问题。

## 5. 后续音乐系统的最终结构

### 5.1 Suno 素材层

Suno 只用于离线生成候选素材：

- 无歌词基础音乐；
- 环境纹理；
- 柔和铺底；
- 风格参考。

正式运行不再实时调用 Suno API。生成后应保存提示词、生成时间、版本信息、处理步骤和文件哈希。

### 5.2 四个音乐层

第一版只需要四层：

```text
L1：基础铺底
L2：旋律或主要乐器
L3：低音/和声支撑
L4：环境纹理或轻微节奏
```

推荐采用混合分层：

- Suno 完整音频保留为 L1 或 L4；
- L2 和 L3 使用学生自主制作的 MIDI 声部；
- 如果 Suno 音频能够高质量分轨，再增加真实音频层。

不要为了形式强行把复杂混音拆成很多低质量分轨。

### 5.3 三个音乐状态

```text
M1：较丰富
M2：过渡
M3：极简
```

M1 保留较多声部和较完整动机；M2 减少旋律密度和高频活动；M3 保留铺底和环境纹理，关闭主要旋律和脉冲。

### 5.4 符号层

学生自主实现：

- 固定调式和和声循环；
- 一个 4–8 音符核心动机；
- 动机重复、删减、延长、八度移动和调式内替换；
- 和声、音域、密度和大跳限制；
- 在乐句边界生成 MIDI 事件。

不要求从零训练音乐大模型。目标是做可解释、可控、可重复的音乐编排器。

### 5.5 波形层

学生自主实现至少四项：

- 分层增益和交叉淡化；
- 低通或高架滤波控制亮度；
- 混响发送量；
- 立体声空间宽度；
- 可选：慢速响度包络和轻度动态范围控制。

波形层必须能够输出实际 WAV 或实时音频流，并计算变化指标。

## 6. EEG 与音乐的关系如何定义

首版已有 EEG 状态输出。后续音乐模块只使用状态概率、置信度和信号质量，不把原始 EEG 直接映射为音高。

关系定义为：

```text
EEG 特征
→ EEG 状态概率
→ M1/M2/M3 音乐目标
→ 音乐层、MIDI 和波形参数变化
```

示例：

```text
transition 概率持续升高
→ 目标从 M1 变为 M2
→ 旋律密度降低
→ 高频亮度降低
→ 旋律层渐出
→ 在下一乐句边界执行
```

这是一种待验证的工程映射，不是“某个 EEG 频段天然对应某个乐器”的科学结论。

## 7. 实施顺序

### 第 1 步：不接 EEG，先完成音乐素材

- 从 Suno 候选中选择一段无歌词、速度稳定、无明显高潮的基础音乐；
- 固定长度、采样率、声道和响度；
- 保存原始素材和来源记录；
- 生成 `base_music_v1.wav`；
- 完成无缝循环检查。

完成标准：基础音乐离线连续播放，没有明显爆音、断裂和突变。

### 第 2 步：制作四个音乐层

优先采用：

```text
Suno 铺底/纹理
+
自主 MIDI 和声/低音/旋律
```

输出至少：

```text
music/layers/pad.wav
music/layers/melody.wav
music/layers/bass.wav
music/layers/texture.wav
```

每层都有独立音量、淡入、淡出、滤波、混响和空间参数。

完成标准：每层能够单独试听、组合、淡入和淡出。

### 第 3 步：制作 M1/M2/M3

先用按钮或键盘手动控制：

```text
M1 → M2 → M3 → M2 → M1
```

每个状态保持 60 秒，重复至少 10 次。

先调好音乐听感，再接 EEG。

完成标准：状态变化明显但不突兀，音乐没有爆音、断音和明显结构破坏。

### 第 4 步：加入自主 MIDI 动机

- 选定一个调式；
- 选定 2–3 个和声循环；
- 手工设计一个 4–8 音符动机；
- 实现完整、删减、延长、移位四种变奏；
- 为音符保存开始时间、持续时间、力度、声部和乐句编号。

完成标准：相同配置和随机种子能生成相同 MIDI；音乐没有明显跑调和极端跳进。

### 第 5 步：加入音乐理论约束

第一版只实现：

- 调式限制；
- 和弦音优先；
- 声部音域限制；
- 大跳惩罚；
- 音符密度限制。

可用代价函数：

```text
总代价 = 音域违规
       + 大跳
       + 不协和
       + 声部交叉
       + 密度偏离
       + 动机破坏
```

完成标准：加入约束后，音域违规、结构破坏和明显不协和减少。

### 第 6 步：加入波形处理

实现：

- 四层独立增益；
- 3–10 秒交叉淡化；
- 亮度滤波；
- 混响控制；
- 空间宽度控制；
- 响度上限。

完成标准：可以在波形和频谱中看到波形层变化，且没有明显咔哒声、爆音和断裂。

### 第 7 步：加入乐句调度

推荐初始参数：

```text
EEG 状态输入：每 3–6 秒
状态平滑：30–60 秒
最小状态保持：20–30 秒
参数渐变：5–20 秒
结构变化：下一个小节或乐句边界
```

控制器状态：

```text
STABLE
PENDING
TRANSITION
FROZEN
FALLBACK
```

完成标准：状态概率短时抖动不会导致音乐频繁切换。

### 第 8 步：接入现有 EEG 输出

不要改现有 EEG 处理。只在 `MusicController.update(state)` 中接入：

```text
StateUpdate
→ MusicController
→ MusicCommand
```

音乐控制器输入：

- W/N1/N2 代理状态概率；
- 未来 N2 概率；
- 置信度；
- 信号质量；
- 时间戳。

输出：

- M1/M2/M3；
- 各层增益；
- 滤波亮度；
- 混响；
- 空间宽度；
- MIDI 动机模式；
- 变化原因。

完成标准：同一段 EEG 回放三次，音乐控制轨迹一致。

### 第 9 步：加入音乐日志

每次更新记录：

```text
时间戳
EEG 输入
信号质量
原状态
目标状态
实际状态
各层参数
MIDI 事件
是否在乐句边界
冻结/回退状态
变化原因
```

必须同时保存实际渲染音频或能够根据日志重新渲染实际音频。

### 第 10 步：完成音乐实验

至少比较：

1. 固定 Suno 音乐；
2. 只调总音量；
3. 分层波形控制；
4. 分层波形控制加自主 MIDI 动机和音乐约束。

所有条件使用同一基础素材和同一状态输入序列。

## 8. 音乐实验指标

### 8.1 波形指标

- RMS/响度变化；
- 峰值和削波；
- 频谱质心；
- 高频能量比例；
- 频谱通量；
- 相邻窗口变化；
- 断裂次数；
- 层进入/退出次数；
- 参数变化速度。

### 8.2 MIDI 指标

- 音符密度；
- 音域违规次数；
- 大跳次数；
- 不协和次数；
- 声部交叉次数；
- 动机保留比例；
- 乐句中间变化次数；
- 相同输入下的重复性。

### 8.3 音乐体验指标

条件允许时评价：

- 音乐连贯性；
- 突兀感；
- 舒适度；
- 音乐丰富度；
- 结构完整性；
- 重复疲劳；
- 愿意继续聆听的程度。

第一版建议把“音乐连贯性”作为主要评价指标。

## 11. GPU 和模型决定

当前不需要租 GPU。

CPU 足以完成：

- MIDI 生成；
- 和声约束；
- 动机变奏；
- 分层混音；
- 滤波和混响；
- 音乐状态控制；
- 网站和日志。

只有在以下任务成为明确瓶颈时才短租 GPU：

- 高质量离线音频分离；
- 批量生成统一风格素材；
- 离线比较开源音乐模型；
- 大量离线渲染。

不建议：

- 从零训练大型音乐模型；
- 只为了替换 Suno 而租 GPU；
- 让云端模型参与实时控制；
- 在正式实验中临时生成随机音乐。

## 12. 最终判断标准

### 保留路线 A：分层波形控制

如果自主 MIDI 音色不够好听，则保留：

```text
Suno 基础素材
→ 分层波形控制
→ EEG 控制增益、滤波、混响和空间
```

这已经是可用的音乐科技系统。

### 升级路线 B：双层音乐引擎

如果 MIDI 声部听感合格，则使用：

```text
Suno 铺底和纹理
+
自主 MIDI 和声、低音、旋律动机
+
自主波形处理
+
EEG 状态控制
```

这条路线具有更强的自主音乐贡献，但不要求自主系统的整首音乐质量超过 Suno。

## 13. 最终现场演示

演示顺序：

1. 播放冻结的 Suno 基础素材；
2. 展示四层音乐和自主 MIDI 动机；
3. 手动切换 M1、M2、M3；
4. 播放预录 EEG；
5. 显示状态概率、音乐层和波形参数同步变化；
6. 注入噪声，展示音乐冻结或回退；
7. A/B 播放固定音乐、只调音量和双层音乐引擎；
8. 展示波形指标、MIDI 指标和重复性结果。

现场必须可以断网运行。Suno 和远程生成服务不应成为现场依赖。

## 14. 首版代码中的注意事项

- 当前 `config.yaml` 和 `config.hardware.yaml` 的音乐配置仍允许运行期音乐生成，需要后续实验模式改为使用冻结本地素材；
- 正式实验应将 `approved_only` 设为 `true`；
- `player_backend` 应选择稳定的本地播放器；
- 不要把 API Key、回调密钥或原始个人数据提交到仓库；
- 不要把公开 EEG 数据描述为自行采集；
- 当前音乐策略文档中的五模式可以保留为旧版基线，但新实验应增加固定、只调音量、分层和双层引擎条件；
- 当前仓库没有根级开源许可证，公开仓库前需要单独核对代码、公开数据和音乐素材许可。

## 15. 最终目标

项目不需要声称“生成了比 Suno 更好的音乐”。最终应证明：

> Suno 提供了高质量基础声音，而学生自主设计的音乐引擎能够根据 EEG 状态对音乐结构和波形进行连续、可解释、可重复的控制，并通过对照和消融实验展示每个音乐技术模块的作用。
