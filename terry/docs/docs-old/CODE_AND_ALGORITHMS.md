## 2. 可选采样率与采集状态

`StartRequest.sample_rate_hz` 限定 250/500/1000，对应硬件命令 ~6/~5/~4。`_sample_rate_hz` 在新会话开始时固定，状态、时间戳及演示生成共享此值。

演示每批 N=fs/10 个样本，时间向量 t=(k+[0,...,N-1])/fs；每通道为不同相位的 8–11 Hz 正弦、1.2 Hz 成分与固定种子噪声之和。固定种子用于演示复现，不是生理数据。

设备请求被受理时 streaming=true，但 connected=false；收到数据才标记连接。无数据持续超过 10 秒抛出错误并由采集线程释放设备。停止发出事件，并最多等待线程 3 秒；线程仍存活时保留引用，禁止新线程复用设备。设备释放归线程所有，避免停止/重启竞争。

每批 timestamp_s=start_sample/fs，是按接收样本计数形成的相对时间，不是设备时钟，因此尚不能检测硬件丢样本或证明真实采样率。WebSocket 订阅者队列最多 8 包，满时丢最旧显示包；这是显示降载机制，不适合作为模型唯一输入或无损实验记录。

## 3. 波形算法

窗口容量 Nwin=round(fs × displaySeconds)。每批入队后仅保留最近 Nwin 个点。每通道计算窗口均值 μ，再显示 y=x−μ。

去均值只是移除该窗口的常量偏置：它不是稳定高通滤波，不消除工频或电极伪迹，也无法修复 ADC 饱和。窗口变化会改变均值。

幅度以用户选定的 ±μV 范围映射到通道行高，超范围显示被裁剪。时间轴按完整窗口容量计算，不足一窗口的样本从右侧排列，避免把短记录拉长。当前纵向限制用于显示，不修改后端原始数据。

每次重绘需要遍历各通道窗口；近似时间/内存复杂度 O(C×fs×T)，C=16。1000 Hz 或长窗口时应后续增加像素级 min/max 下采样，保留峰值，不使用简单抽点掩盖尖峰。

## 4. AISAASGO 异步任务状态机

`submit`：读取纯文本提示词 → 校验非空及长度 → `create_body` 校验模式专属参数 → POST /v1/audios/generations，model=suno-v5.5，显式 custom_mode 与 instrumental=true → 校验任务 ID → 显示 ID → 保存 task.json 和 prompt.txt。

请求构造参照用户提供的媒体客户端：普通模式仅包含 model/prompt/custom_mode/instrumental；自定义模式要求非空 style/title，可附带 negative_tags 与正整数 duration。普通模式出现专属字段直接拒绝，不静默忽略。时长是供应商请求参数而非精确输出保证；纯器乐标志也不能替代听审。API 使用 Accept JSON 和120秒读取超时。

HTTP错误提取 error.message/error.code 或顶层 message，先替换当前密钥、常见sk密钥、Bearer内容和URL，再压缩空白并限制500字符。非JSON错误不显示正文。这比完全隐藏正文更便于定位HTTP400，但本地回执仍按敏感记录管理；参考客户端直接打印完整错误正文的行为未照搬。

没有幂等键保证，因此 POST 绝不自动重试；网络超时意味着“结果未知”，不是“未计费”。若未拿到 ID，应查询供应商后台。

`fetch`：GET /v1/tasks/{id} → 校验响应 ID 一致 → 保存必要字段 → 根据状态处理：

- pending/processing/running/queued/in_progress：按约 10 秒间隔查询，截止后允许同 ID 恢复。
- completed：要求非空 URL 字符串数组，逐个下载。
- failed/cancelled/canceled/error：失败退出，不重新提交。
- 未知状态或结构：拒绝猜测，等待接口核实。

提交与下载请求分开。密钥优先取进程环境，未设置时从 `backEnd/.env` 读取（不覆盖已设置变量）。提交前写本地 `music/submissions/<uuid>.json` 回执，记录模型、起始时间和状态；失败只记录 HTTP 状态或异常类型，不记录响应正文/认证信息。首次旧版提交失败没有这些诊断，无法事后还原具体原因，不能假定未计费。Bearer 密钥只送往固定 API 主机；音频限定 HTTPS img.aisaasgo.org，禁用重定向，不携带认证头，限制扩展名及 100 MiB 大小。临时文件写完且非空才替换为成品，已有文件不覆盖。

候选下载与批准是不同步骤。工具不会创建 approved 记录、不会修改已有音乐清单、不会自动播放。这样在线生成的不确定性不会直接进入用户播放链路。当前只做格式/路径限制，不做音频解码、响度分析或内容审核。

## 5. 素材审核算法

`Manifest`/`Track`/`Review` 使用严格模式校验版本、类型和未知字段，拒绝重复 ID；错误清单整体变成 invalid 空库，避免部分错误被默默忽略。

可播放条件是逻辑与：approved 且审核人非空、日期有效、版权确认、全曲听审确认、授权说明非空、路径合法、文件存在且扩展名受支持。API 接收曲目 ID，而非任意文件路径；禁止越界、绝对路径与符号链接。每次获取文件重新检查审核。

这不是防恶意本机管理员的沙箱：拥有目录写权限的人可替换内容。后续应加入 SHA-256 内容绑定，并在文件变更时撤销审核。浏览器已缓冲的字节无法因撤销审核被追溯删除。

## 6. 网页音量渐变与并发保护

点击播放时先设 volume=0，再等待 HTMLAudioElement.play() 成功。线性渐变：v(t)=v0+(vtarget−v0)×min(1,(t−t0)/D)。默认目标 0.15，上限 0.4，普通渐变 D=1500ms，暂停淡出 D=800ms。

用 requestAnimationFrame 更新音量；新渐变取消旧动画。generation 令牌防止旧 play Promise 在用户停止或切曲后重新启动淡入。隐藏页面、卸载、切曲和立即停止直接静音暂停，不自动循环。

此处处理整曲音量，未做四层混音、重混响或自动 MIDI 生成。浏览器软件音量比例不对应固定声压；需要在目标浏览器、耳机及系统音量下实测。

## 7. 既有音乐调度算法（尚未接入网页）

`music_engine/scheduler.py` 的 `MusicScheduler` 接收 StateUpdate，不直接读取原始 EEG。先判定状态有效且质量达到阈值；无效返回 frozen/fallback 并保持当前状态。

有效概率在时间窗口内按观测点取算术平均。目标状态：N2概率≥0.65 → M3；否则 N1概率≥0.55，或未来N2概率≥0.65且中央theta z≥0.5 → M2；其余 → M1。这些是现有研究规则，不是经过临床验证的治疗阈值。

目标切换需同时满足连续确认次数、最短驻留时间及乐句边界。乐句编号=floor(max(0,t)×BPM/60/phrase_beats)。改变状态后输出预设层增益、波形参数与 MIDI 动机类型。

`layers.py` 管理 pad/melody/bass/texture 与混音；`midi.py` 产生音符计划、质量报告和 MIDI 文件；`waveform.py` 提供低通、混响、宽度、淡变、交叉淡化及指标。真正上线前需验证轨道同步、调性/节拍一致、无效信号恢复和用户停止优先级，不能仅因离线模块存在就启用自动播放。
